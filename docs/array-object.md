# Дизайн: Array и Object

Статус: черновик. Эталон — PHP 8.3; все факты проверены запуском `php` (§5).

Цель: определить модели PHP-массива и PHP-объекта, которых **нет** в Go
(`map` не сохраняет порядок и не даёт copy-on-write; объекты — handle-семантика).
Эти типы — основа для ABI расширений (`ArgArray`/`ArgObject`) и для ООП.

---

## 1. Почему не Go-типы

- **`map[any]any`** не подходит: порядок не сохраняется; ключи PHP —
  только `int|string` с приведением; нужен copy-on-write.
- **`struct`/указатель** не даёт handle-семантику объектов с классами,
  наследованием и late static binding.

Значит нужны собственные VM-типы: `String`, `Array`, `Object[T]`. Они лежат в
Go-heap, а `Slot` адресует их указателем в поле `ptr` (см. §0).

---

## 0. Модель памяти Slot (решено)

`Slot` — 24 байта: `{typ Type; num uint64; ptr unsafe.Pointer}`.

- `num` — скаляры (int/float/bool), без боксинга и аллокаций.
- `ptr` — heap-значение (`*String`, `*Array`, `*Object[T]`), стёртое до
  `unsafe.Pointer` (в одно поле влезают разные типы). Для скаляров `nil`.

Владелец памяти — **Go GC**: `ptr` объявлен указателем, GC его сканирует и
удерживает значение, пока на него ссылается живой слот, а когда ссылок не
осталось — собирает (включая циклы). **Своего `Heap`, handle-таблицы,
free-list и refcount для памяти нет.**

Числа лежат в `num` — GC их не сканирует, поэтому они не могут быть приняты
за адрес (это фундаментально: положить число в pointer-поле нельзя — write
barrier/GC валят процесс с `found bad pointer in Go heap`).

`Object[T]` generic: `T` — данные класса. Ссылка на объект — `*Object[T]`,
в слоте — стёртая до `unsafe.Pointer`. `Context.This[T]() *Object[T]`
восстанавливает тип:

```go
type String struct{ S string }

type Object[T any] struct {
    Class *Class
    Data  T
    Props map[string]Slot
}

func (c *Context) This[T any]() *Object[T] {
    if c.this.ptr == nil { return nil }
    return (*Object[T])(c.this.ptr)
}
```

## 2. Array — упорядоченная хеш-таблица с COW

### Представление

```go
type Array struct {
    // shared — признак разделения для copy-on-write (семантика значения).
    // Это НЕ владение памятью: памятью владеет Go GC. Ставится при копировании
    // значения в другой слот; запись в разделённый массив клонирует его.
    shared    bool
    entries   []ArrayEntry
    nextFree  int64
    // packed — оптимизация (ключи 0..n-1); пока не реализована.
}

type ArrayEntry struct {
    key   ArrayKey
    value Slot      // значение или Reference (когда появятся ссылки)
    live  bool      // false = tombstone после unset
}

// ArrayKey — только int или string (как в PHP).
type ArrayKey struct {
    isStr bool
    i     int64
    s     string
}
```

### Ключи: приведение (проверено, §5)

- `"10"` → int `10`; `"1e2"` → string (не числовое целое); `"01"` → string.
- `1.9` → int `1` (усечение).
- `true` → `1`; `false` → `0`; `null` → `""` (пустая строка).
- Правило: **канонический целочисленный литерал** в строке → int, иначе строка.

### Инварианты

1. **Порядок обхода = порядок вставки.** `unset` не сдвигает соседей.
2. **`nextFree`** = max(целочисленный ключ)+1, **не уменьшается** после unset.
3. **`packed`** — оптимизация: ключи `0..n-1` подряд; `append` — O(1) без индекса.
   Любая вставка неподходящего ключа переводит в mixed (материализует index).
4. **COW:** при копировании значения (`$b = $a`, передача, возврат) массив
   помечается `shared`; запись в разделённый массив вызывает `Unshare()` —
   поверхностную копию, после чего мутирует копию. Вложенные массивы-значения
   помечаются разделёнными при клонировании (рекурсивный COW).
5. **Вложенное копирование:** `$a=[1,[2,3]]; $b=$a; $b[1][0]=99;` — `$a[1][0]`
   остаётся `2` (COW работает рекурсивно через разделение на каждом уровне).
6. **Запись через ref-переменную — без ложного COW:** база записи (`$a[] = v`,
   `$a[k] = v`, `unset($a[k])`, `$a[k] op= v`, вложенные `$a[k][j] = v`, а
   также `global $a`/`static $a`) читается и пишется напрямую через Ref-ячейку
   (OpRefGetRaw/OpRefSetRaw/OpIndexRaw/OpIndexSetRaw/OpIndexSetOverloadRaw).
   Такое чтение **не** помечает массив `shared`: значение гарантированно
   возвращается в ту же ячейку, поэтому `Unshare` копирует массив только при
   реальном втором владельце (`$b = $a`, передача/возврат по значению и т.п.).
   Без этого каждый `$a[] = v` у by-ref переменной копировал бы весь массив
   (O(n²)). `array_push($a, …)` при уникальном владении (не `shared` и
   настоящая Ref-ячейка) дописывает массив на месте.

### Сравнение (проверено, §5)

- **`===`**: рекурсивное равенство ключей и значений **с учётом порядка**.
  `[1,2] === [1,2]` true; `[1,2] === [2,1]` false;
  `['a'=>1,'b'=>2] === ['b'=>2,'a'=>1]` false (порядок важен).
- **`==`**: равенство пар ключ-значение **без учёта порядка**;
  `[1,2] == [2,1]` false (наборы ключей разные: 0,1 vs 0,1 с разными
  значениями — на самом деле здесь false по значениям). Уточнить тестами
  отдельно.

### Итерация

- `foreach` идёт по `entries` в порядке вставки, пропуская tombstone.
- Позиция итератора + защита от модификации во время обхода (как в Zend).

### Значение vs ссылка

- Массив — **value-тип** (COW). `$b = $a` и `$b = $a['k']` копируют значение.
- При появлении `Reference` (§ позже): `&$a[i]` кладёт `Reference` в entry.

## 3. Object — handle-семантика с классами

### Представление

```go
type Class struct {
    Name       string
    Parent     *Class
    Methods    map[string]*Function
    // слоты свойств: имя -> индекс в Object.props
    PropSlots  map[string]int
    // статика — ОДНО хранилище, разделяемое с наследниками (проверено, §5)
    Static     []Slot
    Constants  map[string]Slot
}

// Object[T] — heap-объект; T — данные класса. Ссылка — *Object[T].
// handle-семантика обеспечивается указателем: $b = $a делит один *Object[T].
type Object[T any] struct {
    Class *Class
    Data  T
    Props map[string]Slot // порядок свойств = порядок объявления в классе
}
```

Память объекта держит Go GC (см. §0), поэтому `refs` для времени жизни не
нужен. Отдельный refcount появляется только если понадобится COW-разделение
свойств-массивов (это семантика значения, а не память).

### Инварианты (проверено, §5)

1. **Handle-семантика:** `$b = $a` делит объект; `$b->v = 5` видно в `$a`.
2. **`clone`** копирует объект (свойства), оригинал не меняется.
3. **Identity `===`** — по указателю (`*Object[T]`): `new C === new C` false;
   `$o === $o` true; объект всегда truthy.
4. **Порядок свойств** — порядок **объявления в классе** (для `get_object_vars`).
5. **Динамические свойства** (`$o->x = 1` для необъявленного) — допустимы
   (если класс не запрещает), хранятся отдельно.
6. **Доступ к несуществующему свойству** — warning, значение `null`.
7. **Типизированные неинициализированные свойства** — `Error` при чтении.

### Scope: this / self / static / parent

- `this` — экземпляр; `self` — класс объявления; `static` — класс вызова
  (late static binding); `parent` — `self.Parent`.
- **`self::` разрешается статически, `static::` — динамически.** Проверено:
  `P::test()` вызывает `self::who()` → `P`, `static::who()` → `Q`.
- Кадр вызова уже несёт `this/self/called` (`Frame`), `Context` их отдаёт.

### Статика и наследование

- Статическое свойство — **одно хранилище** на иерархию; `B::$x = 5` видно
  в `A::$x` (проверено). Значит `Static` живёт в `Class`, а наследники
  делят узел родителя (либо ссылаются на тот же слот).

### Свойство-массив

- `$o->arr[] = 3` при COW: массив-свойство ведёт себя как массив-значение,
  но `$e2 = $e1` **делит объект**, поэтому запись в `$e2->arr` меняет
  и `$e1->arr` (проверено: оба стали `[1,2,3]`). Это следствие handle-семантики
  объекта + COW массива: сам массив копируется при записи, но объект общий.

## 4. Влияние на Slot, Heap, ABI

- **Своего `Heap` нет.** Heap-значения (`String`, `Array`, `Object[T]`) лежат
  в Go-heap, `Slot.ptr` держит на них указатель, владелец памяти — Go GC (§0).
- **`Slot`** — 24 байта: `typ` + `num` (скаляры) + `ptr` (heap-значения).
  Для массива/объекта `ptr` — `*Array`/`*Object[T]`, стёртый до
  `unsafe.Pointer`.
- **ABI** дополняется: `ArgArray[T]`, `ArgObject[T]`, `MakeObject[T]` и
  `RetArray`/`RetObject`. `Context.This[T]() *Object[T]` уже реализует
  восстановление типа.
- **`Value`-интерфейс** (граница ABI) — вспомогательный; основной тип значения
  — `Slot`. Кастомные типы расширений — это `Object[T]` (классы), а не
  реализации `Value`.

## 5. Проверенные факты (php 8.3)

### Array

```
$a['x']=1; $a[10]=2; $a['y']=3; $a[]=4;
  keys = ['x', 10, 'y', 11]                    // порядок + nextFree

$a=[0=>1,1=>2,2=>3]; unset($a[1]); $a[]=9;
  keys = [0, 2, 3]                             // tombstone + nextFree=3

$a=["1"]='a';                                  keys=[1]        // "1"->int
$a["10"]="x"; $a["1e2"]="y"; $a["01"]="z";     keys=[10,"1e2","01"]
$a[1.9]='f';                                   keys=[1]
$a[true]='t'; $a[false]='f'; $a[null]='n';     keys=[1,0,""]

$a=[1,2,3]; $b=$a; $b[0]=99;                   a[0]=1, b[0]=99  // COW
$a=[1,[2,3]]; $b=$a; $b[1][0]=99;              a[1][0]=2, b[1][0]=99  // вложенно

[1,2]===[1,2] true; [1,2]===[2,1] false;
['a'=>1,'b'=>2]===['b'=>2,'a'=>1] false;       // порядок важен для ===
```

### Object

```
class C{public $v=1;} $o=new C; $p=$o; $p->v=5;  $o->v=5      // handle
$q=clone $o; $q->v=7;                            $o->v=5, $q->v=7
$o->dynamic=42;                                  $o->dynamic=42  // динамич.
$o instanceof C true; get_class($o)="C"
class A{public static $x=1;} class B extends A{} B::$x=5;
                                                 A::$x=5, B::$x=5  // общее
Q::test() с self::who/static::who                P, Q            // LSB
new C === new C false; $o===$o true; (bool)$o true
get_object_vars порядок                           [a,b,c] (объявления)
$o->nope                                          warning + NULL
неинициализ. типизир. свойство                    Error
$e1=new E;$e2=$e1;$e2->arr[]=3;                   e1->arr=[1,2,3], e2->arr=[1,2,3]
```

## 6. Открытые вопросы

1. **Точная семантика `==` для массивов** без учёта порядка — добить тестами
   (наборы ключей vs значения).
2. **Итерация при модификации** во время `foreach` — модель позиции и защита.
3. **Типизированные свойства** (`public int $n`) — приведение и `Error` на
   неинициализированном.
4. **`ArrayKey` как ключ Go-мапы** — нужен сравнимый тип (сделать `ArrayKey`
   comparable: `isStr bool; i int64; s string` — да, comparable).
5. **COW-разделение массивов** — `refs` на `Array` нужен только для семантики
   значения (когда клонировать при записи), а не для памяти: памятью владеет
   Go GC (§0).

## 7. Реализовано в `internal/vm`

- **`Array`** — две репрезентации: packed (`values []Slot`) и mixed
  (`entries []KV` + `map[ключ]int32`). Итерация — только по `values`/`entries`
  через стателесс `All() iter.Seq2` (как `foreach`; вложенность безопасна).
- **Индекс mixed — `int32`**: потолок 2³¹−1, а PHP сам ограничивает массивы
  `HT_MAX_SIZE = 2³⁰`, т.е. предел недостижим; на всякий случай есть guard
  (`errArrayTooLarge`). Значение int-ключа при этом — `int64` (`ArrayKey.i`),
  держит любой PHP-int.
- **`nextFree`** хранится как `maxIntKey` + `hasInt`, чтобы не терять
  переполнение: `$a[PHP_INT_MAX]=1; $a[]=2;` → `errNextOccupied` (сообщение
  совпадает с PHP), а `$a[PHP_INT_MIN]` → следующий ключ `MinInt64+1`.
- **Внутренний указатель** (`pos`): `Reset/End/Next/Prev/Current/Key` с
  пропуском tombstone'ов; `unset` под указателем сдвигает его на следующий
  живой; копируется при `Unshare`. Отдельно от `All()`. `Next/Prev/Reset/End` —
  COW-запись.
- **Свойства объекта** — packed `Props []Slot` (индекс по `Class`), а не map;
  динамические — в `Dyn`.
- **Опкоды массива**: `OpArray/OpIndex/OpIndexSet/OpAppend/OpLen/OpUnset` +
  пометка `shared` при копировании слота (`OpMove`, биндинг аргументов, возврат,
  чтение/запись элемента) для COW.
- **Ключи** приводятся `keyFromSlot` (bool→int, null→"", float→int, канонический
  десятичный int), сверено с php.

## 8. ООП (реализовано)

- **`Object[T Class]`** — экземпляр класса: данные класса (`data T`) первым полем
  + `props map[string]Value` (PHP-свойства). `data` первым → `*Object[T]` и `*T`
  один адрес, поэтому `ctx.This[*DateTime]()` возвращает указатель на данные.
- **`Class`** — «запечатанный» маркер-ограничение на данные класса (`ClassBase`),
  без `unsafe` в ABI. `int`/`string` не проходят.
- **`ClassInfo`** — рантайм-дескриптор: имя, родитель, методы, конструктор,
  статические свойства, константы. Мост для опкодов (`newObj/cloneObj/getProp/
  setProp`) — неэкспортируемые замыкания, создаются в `RegisterClass[T]`/`NewClass`
  (там `T` известен), поэтому `unsafe` не попадает в авторский ABI.
- **Опкоды**: `OpNew` (с конструктором), `OpPropGet/Set`, `OpMethodCall`, `OpThis`,
  `OpInstanceOf`, `OpClassOf`, `OpClone`, `OpStaticGet/Set`, `OpConstGet`.
  Класс объекта — в `Slot.num` (индекс в пуле классов); `self`/`static`/`parent`
  выбираются B-селектором (0/1/2), LSB — через `ctx.called`.
- **`Context`**: `This[T Class]() T`, `Self()`, `Called()`.
- Тесты: `TestRegOOP`, `TestOOPProgram` (программа на опкодах, вывод сверен с php:
  `1525155`), `TestContextThis`, `TestNewOOPOpcodeStrings`.
